# Sonance documentation site

This folder is Sonance's documentation site, a Chloroplast site in the same per-site pattern as the Modulator library's docs: `SiteConfig.yml` at this folder's root, templates under `templates/`, markdown source pages and assets under `source/`, and a menu in `source/menu.md`. The workflow at `.github/workflows/build-and-deploy-docs.yml` builds the site with the Chloroplast docs action on every push to main and deploys it to GitHub Pages, so the site lives at https://joelmartinez.github.io/sonance/ once GitHub Pages is enabled for this repository with the GitHub Actions source.

The pages carry live examples that run the real library in the reader's browser, not code listings alone. Because Sonance depends on Tone.js, whose dependency files use extensionless module imports that a plain static host cannot resolve, the library reaches the pages as two bundled files under `source/assets/`: `sonance/sonance.bundle.js`, built from this repo's `src/index.js` with Tone.js bundled in, and `modulator/modulator.bundle.js`, built from the `@codecube/modulator` package's `src/index.js`, which the using-the-library page's modulation demo injects into a real engine. Both bundles are plain ES modules the demo scripts under `source/assets/demos/` import by relative path, the same asset shape the Modulator docs use. Refresh a bundle whenever the library it carries changes, with esbuild from the repo root: `npx esbuild src/index.js --bundle --format=esm --minify --outfile=docs/source/assets/sonance/sonance.bundle.js` for Sonance, and the same command pointed at the modulator package's entry and output path for Modulator. A future Chloroplast engine feature for library bundle delivery would replace this manual refresh; that need is already on record in the Chloroplast project from the Modulator docs work.
